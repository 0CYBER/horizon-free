# Bulk unary density evaluation benchmark

Dispatching unary operations once per bulk buffer reduced initialized Overworld terrain generation from 12.271 to 10.566 ms/input chunk (13.89%) with one worker and from 3.838 to 3.408 (11.19%) with four. Terrain plus decoration improved 11.70% and 9.48%. A second seed/site improved terrain 13.66% and 13.70%. These are incremental results against baseline `e4f8154cb4115aa1ee622381d9b12387cdf515d4`.

Each case used one discarded pair and five measured alternating baseline/candidate pairs. The primary case used seed 12345, center (0,0), 256 terrain chunks and 196 decorated interior chunks. An offset 9×9 generation pass initialized the seeded generator without pre-generating target chunks. The second site used seed -1 at (32,-32). Timing is complete terrain wall time divided by input count; combined results retain border work. Cold initialization was measured separately.

Nether terrain medians improved 3.15% / 2.03% with one/four workers; End improved 3.03% / 5.39%. Some individual Nether/End pairs regressed or had large favorable outliers. Gains are workload-dependent and should not be generalized to every seed, biome, compiler, or platform. Peak RSS was effectively unchanged and no new heap buffer was introduced.

Measured on AMD Ryzen 5 5600X, 32 GiB RAM, Linux, Rust 1.99.0, optimized `fast` profile (release optimization, LTO off, 16 codegen units). Builds and measurements ran sequentially; background desktop activity was not isolated. The benchmark used the existing chunkgen benchmark with identical optional initialization and exact elapsed-time instrumentation on both revisions. `crates/horizon-world/examples/chunkgen_bench.rs` provides the standard workload entry point; its human-readable thread-multiplied ms/chunk display must not be mistaken for elapsed/count.

Validation passed: 191 targeted Rust tests; fresh pinned Java client/server density parity (15,524,627 lines each); terrain-fill parity (114 fixtures, 200 fills, 7,950,873 lines per Java side); and 24 exact terrain/decorated region comparisons across three dimensions, two seeds/sites, and one/four workers. Snapshots included block states and palettes, quart biomes, entities/block entities, scheduled ticks, all six heightmaps, ordered postprocessing, non-air counts, and chunk metadata. This establishes parity within the declared corpus, not complete gameplay parity.

The repository quick PR check also passed public-tree validation, Python tests, formatting, clippy, and core tests. Generated timing files, diagnostic runners, patches, and validation logs are retained locally outside the repository and are not part of this PR.
